# 人物行迹地图指南

本文是给执行者（Claude Sonnet 5.5、Codex 或人工）的操作规范。照本文给一位 v3 人物的生平履历标注地点，页面就会自动生成“行迹地图”，并通过自动校验。

- 状态：初版（2026-11-13）。样例是 A 级刘备（详见 §13）：

  | 样例 | 种子文件 | 页面 |
  |---|---|---|
  | 刘备 | [profile_v3_liubei.py](../scripts/profile_v3_liubei.py) 中 `careers` 各行的 `place` | `/people/liubei/#trajectory` |

- 本文是 [person-template-v3.md](person-template-v3.md) 的补充。人物卡的取证规则（R1–R10）照旧适用；本文只规定地点怎么标。

---

## 0. 执行者须知（先读）

1. **只标 v3 人物。** 地点写在 v3 种子文件 `careers` 的行里。还没迁到 v3 的人物（诸葛亮、孙权、周瑜、陆逊、司马懿、曹操）等迁移时再标。
2. **一次只改一个人物**，只改 `scripts/profile_v3_<id>.py`。不要改 `src/components/`、`src/lib/`、校验脚本和江山时序项目。
3. **不要提交 git，不要执行 `npm run build`**（理由同人物卡指南 §0）。
4. **书中写法必须出自本书。** 显示给读者的地名（`name`）必须在本行的 `when`、`title` 或 `text` 里出现过。
5. **查询名可以借助地理常识。** `query` 只用来让地图找到位置，不显示为史实，可以用今地名或江山时序认得的古地名代替。
6. 遇到下列情况就停下汇报：本行地点在书中有矛盾；地图解析到了明显错误的位置，而且换几个查询名都不行。

## 1. 背景与分工

本站和江山时序（`github/jiangshan-map`，本地端口 8000）分工如下：

| 本站负责 | 江山时序负责 |
|---|---|
| 哪一行标地点、书中写法、取景年份 | 把地名解析成坐标 |
| 页面上的地点列表和说明 | 画疆域底图、路线和站点 |

本站只通过网址参数调用江山时序（`?year=…&place=…`），不改它的代码。

**为什么不直接用江山时序自带的人物行迹（`?person=liubei`）**：那份行迹的文字不受本站“事实必须出自 book.json”的约束，里面有本书没有的说法。所以路线一律由本站的生平履历生成。

## 2. 硬性规则

| # | 规则 | 由谁检查 |
|---|---|---|
| M1 | 一行最多一个地点，标**本人当时所在地**，不标部将作战地、出使目的地或建议攻打的地方。 | 人工审查 |
| M2 | `name` 必须出现在本行的 `when`、`title` 或 `text` 中。 | `validateAtlasPlaces` |
| M3 | `query` 必须能被江山时序解析，解析结果的今省份要与 `province` 一致。 | `atlas-places.mjs check` |
| M4 | 地图解析出的地名（去掉括号注释后）与 `name` 不同时，必须写 `approx=True`；相同时不写。 | `atlas-places.mjs check` |
| M5 | `mapYear` 是整数。`when` 里有年份时，`mapYear` 必须落在这个区间内。同一人物各行的 `mapYear` 不能倒退。 | `validateAtlasPlaces` |
| M6 | 书中没写地点的行不标，不从外部材料补地点。 | 人工审查 |

## 3. 数据格式

在 `careers` 的行里加可选字段 `place`：

```python
dict(id='liubiao', when='201年后，确切月日未载', title='投刘表，屯新野', ...,
     place=dict(name='新野', query='新野', province='河南', mapYear=201)),
dict(id='yiling', when='221—222年', title='东征孙权，猇亭大败', ...,
     place=dict(name='猇亭', query='夷陵', province='湖北', mapYear=222, approx=True)),
```

| 字段 | 必填 | 含义 |
|---|---|---|
| `name` | 是 | 书中写法，页面上显示这个。 |
| `query` | 是 | 交给江山时序解析的地名。能直接用 `name` 就用 `name`。 |
| `province` | 是 | 今省份简称，如 `'河北'`、`'重庆'`，用来发现解析错位。 |
| `mapYear` | 是 | 取景年份，只决定地图显示哪一年的疆域。页面上不显示，读者看到的仍是 `when`。 |
| `approx` | 否 | 地图只能定位到附近时写 `True`，页面会注明“地图位置为近似”。 |

数据流向：种子 `careers[].place` → `profile_v3.py`（原样带出）→ `cards.json` 的 `people[].milestones[].place` → 页面。

## 4. 选点规则

1. **标本人所在地。** 例：刘备 218 年那行写“分遣吴兰、雷铜入武都失利”，刘备本人在阳平关，所以标阳平关，不标武都。
2. **一行有好几个地方时，标本行主事发生的地方。** 例：“与刘璋决裂，攻取成都”一行先后经过涪、雒、成都，标成都。
3. **建议、谋划不标。** 例：“建议乘曹操北征袭许”只是没被采用的建议，刘备人在新野，不标许。
4. **书中没写地点就不标。** 例：“三顾诸葛亮”一行，《先主传》没有写隆中，不标；不能用《汉晋春秋》或常识补上。
5. **相邻两行地点相同时都可以标**，生成路线时会合并成一站。

## 5. 取景年份 `mapYear`

| `when` 的写法 | `mapYear` 取法 | 刘备的例子 |
|---|---|---|
| 单一年份 | 就用这一年 | `194年` → 194 |
| 区间 | 本地点对应的那一年。引文写明年份就用它，否则取区间起始年 | `212—214年` 攻取成都，引文“十九年夏” → 214 |
| 确年未载 | 根据 `when` 文字或相邻行能确定的最早年份；仍不能确定就和上一行相同 | `寄居荆州期间` → 201（上一行投刘表的年份） |

`mapYear` 只是选底图用的，不算作史实断代，所以不要求引文支撑；但不能和 `when` 冲突（M5）。

## 6. 查询名与近似

江山时序的地名库以名城、名关为主，三国县邑不全。常见三种情况：

| 情况 | 例子 | 处理 |
|---|---|---|
| 能直接识别 | 新野、赤壁、成都、阳平关、定军山 | `query` 同 `name`，不写 `approx` |
| 识别到附近的地方 | 公安 → 江陵；博望 → 新野；沔阳 → 定军山 | `query` 同 `name` 或换成更近的名字，写 `approx=True` |
| 识别不了 | 安喜、小沛、雒城 | 换查询名：安喜 → `中山`，小沛 → `沛国`；写 `approx=True` |
| **识别错位** | 平原 → 灵州（宁夏）；海西 → 青海；涪 → 葭萌 | 必须换查询名：平原 → `平原郡`。M3 的省份核对就是为了发现这种情况 |

查询前先用工具试：

```bash
node scripts/atlas-places.mjs lookup 安喜 中山 平原 平原郡 --year 184
```

输出每个名字的解析名、今地、今省份、坐标和当年所属政权。识别不了的会显示“未识别”。`--year` 要用打算写的 `mapYear`，因为解析结果会随年份变化（见 §13）。

## 7. 页面效果

有地点的人物，页面会多出两处：

1. **生平履历**：有 `place` 的行，在“重要经历”下方显示“📍 新野 · 在地图上看 ↗”，在新窗口打开江山时序那一年、那个地点。近似地点显示为“📍 猇亭 · 地图近似 ↗”。
2. **行迹地图**（`#trajectory`，紧接生平履历，并加入侧栏目录）：至少有 2 个不同地点时才出现。内容包括：
   - 嵌入的全程路线图。时间轴限定在第一站到最后一站，读者可以逐站播放。
   - 地图上的站名是江山时序的名字（例如安喜会显示成“中山”），所以下方列出本站的地点清单：序号 · `when` · 书中写法 · 对应经历。
   - “在江山时序中打开完整地图 ↗”。

地图地址由 `src/lib/atlas.ts` 统一生成。本地默认 `http://127.0.0.1:8000/`，发布时用环境变量 `PUBLIC_ATLAS_BASE` 指定。

## 8. 单人标注步骤

1. 列出年表：
   ```bash
   python3 -c "import sys;sys.path.insert(0,'scripts');import profile_v3_<id> as m;[print(c['id'],c['when'],c['title'],'|',c['text']) for c in m.PROFILE['careers']]"
   ```
2. 按 §4 逐行判断标不标、标哪里，先在草稿里写出 `name`。
3. 用 `atlas-places.mjs lookup` 试查询名，按 §6 定下 `query`、`province`、`approx`。
4. 按 §5 定 `mapYear`。
5. 写进种子文件，运行 §9 的验收命令，直到全部通过。
6. 用浏览器打开页面，逐站点一下“在地图上看”，确认位置大致正确。

## 9. 验收命令与通过标准

在仓库根目录依次运行：

```bash
python3 scripts/create_cards.py > /tmp/gen.log && tail -1 /tmp/gen.log
node scripts/validate-content.mjs
node scripts/atlas-places.mjs check <id>
npm test
npx astro check
npx astro build --outDir /tmp/sgz-dist
```

通过标准：

- validate、`atlas-places.mjs check`、test、astro check 均无错误。
- `check` 列出的每个近似地点，都已在浏览器里看过位置。
- 用 `python3 -m http.server 4331 --directory /tmp/sgz-dist` 打开 `/people/<id>/#trajectory`：路线图能加载（需要 8000 端口在运行），站数与清单一致，320px 宽度下没有横向溢出。

`atlas-places.mjs` 依赖本机的江山时序项目（默认 `~/ai/github/jiangshan-map`，可用环境变量 `JIANGSHAN_DIR` 指定），所以不放进 `npm run build`。

```text

```

## 11. 常见错误

| 报错 | 原因与处理 |
|---|---|
| `atlas place name not in row` | `name` 不在本行的 when/title/text 中。改用文中的写法，或者这行本来就不该标。 |
| `atlas mapYear outside when` | `mapYear` 超出 `when` 写的年份区间。 |
| `atlas mapYear goes backwards` | 比上一行的 `mapYear` 小。检查年表顺序或取景年。 |
| `未识别` | 江山时序找不到这个查询名。按 §6 换名。 |
| `province mismatch` | 解析到了别的省，常见于同名地，如平原、海西。换查询名。 |
| `approx should be True/False` | 按 M4 补上或去掉 `approx`。 |

## 12. 当前限制与后续

1. 江山时序的嵌入地图没有改站名的参数，地图上显示的是它的地名，本站只能在清单里对照。
2. 事件页暂时没有地图链接。等事件数据有了地点字段，再按同样的方式补。
3. 诸葛亮等 6 位旧结构人物，迁移到 v3 时一并标地点。

**可以借鉴的地方**：

- **用 `mapYear` 查询，不要用随手的年份。** 同一个地名在不同年份可能解析成不同地点：永安在 196 年解析为白帝城，在 223 年解析为永安本身。`check` 用的就是 `mapYear`，所以 `approx` 以它的结果为准。

- **宁可近似，不可错位。** 平原、涪两处如果直接用书中写法查，地图会标到宁夏和广元，看起来“识别成功”，其实是错的。省份核对能抓住平原这类错误；涪这类同省错位只能靠逐站在浏览器里看。
- **不标的行同样重要。** 隆中、许这两处如果标上，路线会更“好看”，但前者不出自本传，后者不是刘备去过的地方。
